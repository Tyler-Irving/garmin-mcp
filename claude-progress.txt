Bugs fixed mid-session (worth knowing for the future):
- structlog defaulted to stdout, which collided with the MCP JSON-RPC stream in stdio mode and broke Inspector "Connection Error". Fix: routed structlog (WriteLoggerFactory file=sys.stderr) and stdlib logging (basicConfig stream=sys.stderr) to stderr.
- Relative imports (from .auth import ...) failed when mcp dev loaded server.py as a top-level module without parent package context. Fix: switched server.py and __main__.py to absolute imports (from garmin_mcp.auth import ...).
- garminconnect 0.3.3 requires Python 3.12+. Bumped requires-python and Dockerfile from 3.11 to 3.12.
- Body-battery parser had wrong max/min logic. Fix: compute from timeline values rather than misreading "charged" as a max.

Assumptions made:
- Single-user model. One MCP_AUTH_PASSWORD, one Garmin account.
- Garmin account has MFA disabled. The wrapper uses return_on_mfa=False and cannot prompt for an MFA code on cold start.
- Refresh tokens, registered DCR clients, and pending login states live in process memory and are lost on cold start. Access tokens (JWTs) survive because they are stateless.
- Cloud Run target: us-central1, min=0, max=1 instances, 512Mi memory, 1 CPU. Cache cleared on cold start is acceptable for personal use.
- Unofficial garminconnect package is the right call; no fallback if Garmin changes its API.
